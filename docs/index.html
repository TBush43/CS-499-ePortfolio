Professional Self-Assessment

I'm a platform engineer pursuing a software engineering career. Through my work, I've learned that a tool can function correctly and still slow people down when its user interface isn't clear. That's why I care about straightforward navigation, useful feedback, and making the next step easy to find. My computer science coursework has also changed how I approach a feature: I think about who'll use it, what data it needs, how it might fail, and who'll maintain it later.

Platform engineering has made me attentive to people who depend on shared systems. In CS 499, I've made my decisions reviewable through a code review, source comments, and narratives for a broader audience. My instructor asked for clearer comments, so I added concise explanations of intent and non-obvious choices. This was an individual capstone, but responding to feedback and making decisions legible are habits I'll bring to a team.

My coursework taught me to consider edge cases and trade-offs. For the coaching priority feature, I combined related records by student ID and used a bounded priority queue to keep only the top three students for review. The score includes readable reasons, and fixed-date tests cover ties and boundary cases. In the app, I separated screens, service rules, and data access, then used four related SQLite tables to preserve records across launches. Nineteen local unit tests pass; on-device database testing remains to be verified.

My platform-engineering perspective also makes me careful about security claims. I removed the original SMS permission and misleading login, validated input, used bound SQL arguments, and excluded the database from Android backup. The prototype still lacks authentication, access control, and database encryption, so it must use fictional student information only. The code review below identifies the original weaknesses; the three enhancements show how the design, algorithm, and database work build on one another.

Course Outcomes

The code review and narratives explain my design decisions. The enhanced app demonstrates software structure, an explainable ranking algorithm, and relational data storage. Input checks and backup exclusions show progress on privacy and security, while the prototype's missing sign-in and encryption remain important limitations.

  1. Collaborative decisions: The code review, source comments, and narratives make design choices visible to an instructor, teammate, or manager; I revised the comments in response to feedback.
  2. Professional communication: The video explains planned changes, the narratives reflect on each enhancement, and this site presents the progression for a non-specialist reader.
  3. Algorithmic solutions: The follow-up ranker uses maps and a bounded priority queue, with deterministic tests and an explicit complexity trade-off.
  4. Useful computing tools: Android, Java, SQLite, Gradle, unit tests, and lint support a working coaching workflow rather than isolated demonstrations.
  5. Security mindset: Validation, bound SQL arguments, and backup exclusions reduce some risks; the lack of sign-in and encryption is clearly disclosed.
